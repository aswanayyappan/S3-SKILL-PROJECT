OBJECTIVE & PROBLEM STATEMENT

  • Solar battery health and depth of discharge require continuous automated monitoring.
  • Fluctuating DC loads cause voltage sag and sudden battery drain under field conditions.
  • Inductive DC pump motors draw heavy startup inrush current and risk stall burnout.
  • Quiescent sensor offset introduces off-time voltage (1.18V) and current (0.2A) calculation bias.
  • Traditional energy meters fail to provide load-level intelligence or predictive fault detection.
  • Automate energy monitoring using ESP32, ACS712 current sensors, and precision dividers.
  • Implement dual-layer zero-bias rectification to guarantee true 0.00V / 0.000A at idle.
  • Train an offline PyTorch Neural Transformer model (97.14% accuracy) for electrical anomaly classification.
  • Integrate Groq AI Copilot and MCP tool calling for conversational energy auditing.

⚡ Critical Electrical Safety Rules

  • ESP32 ADC 3.3V Overvoltage Protection: The ACS712 operates at 5V $V_{CC}$ and outputs 2.5V at zero current, reaching up to 4.5V under load. Connecting this directly to an ESP32 ADC pin would damage the MCU. A matched $10\text{k}\Omega/10\text{k}\Omega$ voltage divider scales the sensor output to $\le 2.5\text{V}$, safely below the 3.3V threshold.
  • 1N4007 Inductive Flyback Clamping: The DC motor generates negative inductive back-EMF spikes during de-energization. A 1N4007 reverse-biased diode is wired across motor terminals to absorb transient kickback.
  • Star Common Ground: All sensor grounds, the 5V DC bench power supply, and ESP32 GND share a unified reference to eliminate floating ADC errors.

🔮 Future Scope Architecture

Hybrid Electrical ML & Conversational AI System

Decoupling continuous real-time electrical event detection from natural-language LLM orchestration

🧠 Two-Tier Intelligence Principle

Rather than burdening an LLM with millions of raw ADC sensor streams, the system cleanly separates responsibilities:

  • Electrical ML Engine: Operates 24/7 locally at the edge. Detects waveform anomalies, surges, and fault signatures without requiring internet connectivity.
  • Groq Conversational LLM: Operates on-demand when users ask natural-language questions, querying strictly verified event records via function calling.

📡 5-Stage Data & Query Pipeline

  1. Modular Switches: Discrete measurement of $V, I, P, E$ per socket.
  2. Holder ESP32: Aggregates switch telemetry over local serial bus.
  3. Edge ML Engine: Continuous waveform anomaly classification.
  4. Event Database: Stores structured event tuples with confidence scores.
  5. Groq Function Calling: Translates user queries into database calls.
